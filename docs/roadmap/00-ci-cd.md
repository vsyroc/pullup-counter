# Эпик 0. Настроить GitHub Actions и деплой на Orange Pi

## До первой фичи

- [x] Подготовить [CI workflow](../../.github/workflows/ci.yml) с запуском `go test ./...` на push и PR в `dev` и основную ветку. Для PR в основную ветку проверять, что источником служит `dev` этого репозитория.
- [ ] Проверить запуск CI на GitHub. Включить для `master` защиту с обязательным PR и успешной проверкой `test`. Проверить путь от ветки фичи через `dev` в `master`.

## К первому релизу

- [ ] Подготовить сервис systemd для автозапуска Go-бинарника и перезапуска при сбое. Хранить SQLite и настройки отдельно от бинарника.
- [ ] Настроить доступ GitHub-hosted runner к Orange Pi напрямую по SSH. Использовать ключ деплоя из GitHub Actions Secrets и проверять ключ хоста.
- [ ] Запускать отдельный релизный workflow при публикации тега `vMAJOR.MINOR.PATCH`. Проверить, что коммит тега входит в `master`. Для этой ревизии выполнить тесты и собрать бинарник под архитектуру ОС платы.
- [ ] После успешной сборки доставить бинарник по SSH, перезапустить сервис и проверить его состояние. Убедиться, что после обновления бот восстановил историю и ожидающее напоминание из SQLite.

**Готово, когда** обычный push запускает CI, а публикация тега проверенного коммита приводит к установке именно этой версии. В GitHub Actions виден результат деплоя, на Orange Pi сервис работает с сохранёнными данными.
