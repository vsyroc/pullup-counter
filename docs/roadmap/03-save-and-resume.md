# Эпик 3. Сохранить результаты и восстановить открытый день

- [ ] Создать схему SQLite для дневников и расписания. Хранить базу на Orange Pi в постоянном каталоге данных сервиса. Для каждого Telegram ID сохранять прохождение недели и день программы, фиксированное UTC-смещение, статус отдыха или паузы, состояние расписания, историю и открытую тренировку с фактическим временем подходов, временем сохранения, исходными сообщениями и ожидающими подтверждения правками.
- [ ] Отправлять квитанцию после успешного сохранения. Весь подтверждённый ввод, завершение плана, дополнительные подходы и соответствующие изменения таймеров фиксировать в одной транзакции SQLite.
- [ ] После перезапуска продолжать с первого незаполненного подхода. Восстанавливать срок напоминания по времени последней записи и учитывать уже отправленные сообщения.
- [ ] Связать состояние тренировки с Telegram ID автора в группе и в личке. Хранить личный `chat_id` для доставки, а пару исходных `chat_id` и `message_id` для исправлений. Учитывать обработанный `update_id` вместе с результатом обработки, чтобы повторная доставка не засчитала подход дважды. При ошибке чтения или записи сообщать причину и сохранять предыдущие данные.

- [ ] При первом подходе зафиксировать дату тренировки по действующему UTC-смещению. Смена смещения сохраняет эту дату до завершения и в истории. Для новых тренировок и отображения времени ближайших отправок использовать новое смещение.

**Готово, когда** после перезапуска за полночь видны два ранее записанных подхода, новая запись становится третьей, а повторная доставка пятого сообщения оставляет в истории одну завершённую тренировку.
